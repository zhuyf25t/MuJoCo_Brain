# 逐轮复核后的改动与待验证问题

日期：2026-10-02。前半部分记录 deepseek-flash、thinking=disabled 阶段的修改与实验；后续开启思考并改为 low 的当前配置与结果见文末对应记录。未引入独立距离估计器，未启用程序几何抓取判定。

## 已完成的修改

1. 球定位必须给出紧贴球体的圆心、半径和可见性，排除阴影与反光；网页按原图像素比例绘制，不再用固定大小的小圆代替轮廓。
2. 每张新图先定位一次，再分析上一段纯移动；匹配、移动规划共用本轮定位，运动样本选择目标作参照时复用两次检测，不能另造一组圆心。
3. 匹配结果增加左右位置和远近，短 prompt 明确结合球大小、地面透视、夹指间隙与遮挡，禁止仅凭居中判可抓。
4. 移动规划同时收到匹配结论、相同 reach 参考和方向经验；提示像素变化率只适用于局部深度，不能拿远球速率套近球，也不能把被推走的球当静物。
5. 保持 0.2 秒首次探测、正式动作至多 2.0 秒、最多 64 决策轮、说明至多 340 字符且超限完整报错；不截断返回，不暗中切换思考模式。
6. 日志升级 v3，旧经验自动归档并撤回旧运动分析，reach 原图可重新分析；旧复盘记录保留。
7. 根 README 说明整体项目与文件导航，模块 README 分别说明所有模块、prompt、输入输出及替换方式。

## 还需要验证的问题

| 问题 | 当前理解与下一步判断依据 |
| --- | --- |
| 是不是一次函数？ | 理想匀速路程随时间近似线性；投影球大小约随 1/深度变化，像素位置与地面距离通常非线性；实际车轮滑移等另计，不能将这三者混成一种“速度”。 |
| 定位换成圆就能准吗？ | 不能保证；圆补全了物体尺寸信息，也让错误更容易看见，但仍需逐帧检查 disabled 模型是否圈中球。 |
| 共享错误坐标是否仍有问题？ | 会；共享消除模块之间各说一套，但上游若看错，错误仍会传递，匹配模块应在明显矛盾时返回 unknown。 |
| 一张 reach 图足够吗？ | 它只能提供夹指的投影候选和尺度线索，不是成功抓取标定，也不能单凭它证明不同大小球都可抓。 |
| 最近球是否被可靠跟踪？ | 相似球之间切换、遮挡和球被推动都可能污染运动样本；本次让分析模块核对同一静物，但这仍是模型能力假设。 |
| 为什么每轮移动仍慢？ | 物理移动秒数与 API 等待是两部分；要分别看网页“仿真时间”和“API 等待”，不能只把墙钟时间长归因于车速。 |
| 两条样本够不够？ | 每类两条是当前设计约束，同方向只保留最新样本，无法覆盖各种深度、负载和路面；本次没有扩库。 |
| 模型的左右判断靠什么？ | 车头图 x 向右；目标在左需要左转，左转又会使静物向画面右移，两种“左右”不可混淆，运行时仍需看实际输出是否遵守。 |
| drop 可达范围是否充分？ | reach 参考不等于 drop 释放轨迹，需以后用真实成功/失败样本检查，当前仍由视觉模块判定。 |
| 仿真与真机差异？ | 相机、姿态、抓取接触和行驶速度须重新标定；尤其当前仿真含接触后吸附机制，不能将仿真成功直接视为真机成功。 |

### 用户指出的多球目标切换

这不是只有模型的问题：`find_ball` 目前每帧选择最近可达球，上一目标仅传文字身份，**没有可靠的跨帧目标锁定**。本次实现的“共享定位”范围是一张当前图上的各模块；它不等于跨图跟踪。

第 6 轮输出球心 `(0.325, 0.588)`，从保存原图看该点已落在地面；第 7 轮输出 `(0.476, 0.196)`。运动分析文字同时提到“原目标为近处球、当前目标为远处球”，却返回 `valid=true/source=shared_target`。程序因此将两组不可靠对应的数据相减并入库，后续规划又引用该异常趋势。仅凭输出标签不能断言每一轮都切球，但可以确认：定位错误、跨帧对应错误、运动推理错误叠加存在。

待下一次架构选择：找到目标后保持该目标，只有丢失/受阻/结束时才重新选；同一球对应关系应有单独、可验证的结果，确认不了就不把这对目标写入速度经验。仍需决定用专门的视觉跟踪器还是模型对比前后图；本次未暗中引入跟踪器或替换模型。

测试：重复资料申请修复后完整回归 92 项通过；GUI 错误显示两项针对性检查通过；报告四项检查通过，覆盖运行中快照的尾部处理。浏览器已确认完整记录显示“已结束”、第 12 轮为 back 0.8 秒、轮廓圆的显示宽高一致。

## 2026-10-02：DeepSeek low 思考模式 GUI 试跑
