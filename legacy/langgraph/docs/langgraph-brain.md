# LangGraph + DeepSeek Brain

```powershell
.\.venv-gui\Scripts\python.exe -m pip install -r requirements-langgraph.txt
.\.venv-gui\Scripts\python.exe -X utf8 run_collect.py --brain langgraph --episodes 1 --gui --out output/langgraph
```

沿用项目 `.env` 的模型、端点、密钥和请求选项，模型需支持多图与工具调用。
Windows 使用 `-X utf8`，避免模型日志里的箭头等字符在重定向到 GBK 输出时中断采集。
任务设计见 [langgraph-design.md](../brains/langgraph-design.md)。

## 三个任务节点，每轮预测一段连续动作

```text
run_collect 拍车头图
  → decide → START → explore / pick / place（按phase选一个）→ END → list[Decision]
  → run_collect 顺序执行全部动作、记录轨迹
  → 下一轮新图
```

每个阶段节点一次完成：核对上批指令、看图检查预测、更新经验、规划下一批动作及预期。
通常每轮两次模型请求：先只看当前图读取事实，再结合历史规划。完全相同的当前图复用已读取的事实。
观测不含任务进度、历史照片、旧坐标或预测；事实临时存在 RoundContext，不添加长期顶层状态。
规划格式或动作参数不合法时允许修正一次，仍不合法则返回
`observe` 并保留状态继续下一轮，不因此结束整集。整批先校验通过再返回，不执行半份非法计划。

提示词用普通话说明目的、具体建议和看什么判断结果；操作建议保留在“一种可行方式”的括号里。
`explore` 要找到低位张爪朝下、指尖贴近地面、两指能包住地上球的姿态，保存实图和可抓球心区域。
不知道关节方向时，一次只改变一个关节并比较前后图，看手指离地和朝向怎样变化；当前图已合适就直接利用，
不用重复试验。影子可帮助判断爪与地面的关系。探索时车身不动，便于比较操作效果。
低位确定后，肘保持不动，只调整肩，直到球和前方路面看得清、爪不拖地，再保存就绪图和肩的操作。
（一种可行方式：张爪并找到低位；下一轮保存低位图，再固定肘抬肩；看到前方视野清楚的新图后保存就绪图（仅供参考））
如果必须改肘，目标是在 `explore` 重新建立低位和就绪这对参考，不能继续假定只降肩就能返回旧低位。
约3-5轮只是预算参考，一个阶段可跨多轮，一轮可有许多操作；首次学习低位时需要在那里结束一批，才能获得低位实图。

`pick` 在就绪姿态下找绿色球，通过车身转向、前进让球进入低位参考的抓球区域。
抬高后爪口在图中的位置不是地上的抓球区域。距离有把握时，一批可连续接近、降肩、闭爪、抬肩；肘保持低位时的位置。
抓后抬肩的目标是球离地且能看见球和部分手指，便于下一轮判断；空爪找球时的就绪姿态则以让开前方视线为目标，
允许爪出画。看清抓空后张爪并回到就绪姿态重试；看不清则保持闭爪，优先只调肩恢复观察。
`place` 运送到箱口、释放、下一轮确认入箱；投放时可按需要改肩肘，但失败后重新捡球前需要恢复或重建原来的抓球关系。

上轮预测抓取后仍为 `pick`；下一轮当前图看清持球，才改为 `place`，并可在同一次模型请求
直接规划找箱动作。节点含阶段边界检查，入口节点与本批动作阶段可能不同，不为同张图额外调用模型。
批次尽量推进当前阶段，到阶段边界或需要新图纠正的位置结束。

终端每轮打印 `当前动作阶段=pick（捡球）`；发生切换时另列 `阶段切换 explore → pick`。
请求前的“入口阶段”表示沿用上轮状态，动作前打印的“当前动作阶段”才是这批要做的工作。

提示词明确目标是绿色/黄绿色网球，橙色或棕色机械关节不是球。机械臂没有独立腕关节，
夹爪随小臂转动；肩肘调整需同时预测位置和朝向。`reach/carry/drop` 的名字不保证爪朝下，
尤其不能把 `drop` 当作自动保持朝向的抬升。这些是结构常识，不向模型提供预设角度或仿真位姿。

动作参数遵循原工具定义，不再额外限制每个底盘动作最多 0.6 秒。
没有每阶段 16 动作、4 次抓取或独立无进展计数上限；整集沿用 `MAX_DECISIONS=32`。
同批中没有新图，闭爪后不能紧接着松爪；`done` 需单独返回，防止用预测冒充完成。
可能持球且看不清时保持闭爪并改善视野；初始尚未尝试抓取时可张爪准备。
空爪判定也必须看见实体手指及夹持空间为空；只有棕色关节、手背或没有绿色球不能证明空爪。
记录抓取几何候选不必同时判定空爪：已执行张爪且没有可能持球记录时，即使 `holding=unclear` 也可
保存当前可见的张爪候选和区域。影子可辅助实体爪的高度/朝向判断，不能单独当成实体爪或持球证据。
抓空后的目的为恢复能够再次接近的就绪状态。
（一种可行方式：确认抓空后张爪，回到探索得到的就绪姿态，再搜索或重新接近（仅供参考））
旧持球判断受到质疑或参照失效时，可以从 `place` 回 `explore` 恢复视野；这不会清空持球历史，
也不解除不确定时禁止张爪的约束。回 `pick` 仍须当前看清空爪或掉球。
`observe` 不会在批次中间提供新图，非空批次自然结束后已有下一张图，无须每批额外追加。

## 状态与验证过的肩动作

| 字段 | 内容 |
|---|---|
| `phase` | 当前实图支持的探索/捡球/投放阶段 |
| `calibration.grasp / clearance` | 低位抓取图及可抓球心区域、抬高就绪图 |
| `calibration.moves` | `to_clearance / to_grasp` 两段实图验证过的肩动作，包含前后图片及 history 边界；初始均为 null |
| `calibration.lessons` | 最近四条新观察，稳定的肩动作独立保留，不被文字更新覆盖 |
| `arm_anchor` | 最近从图里认出的 grasp/clearance 和当时照片；用于截取后续试验片段，不代表当前角度 |
| `visual_memory` | 最近目标图、持球证据；bin 图保留给接近/调臂前后比较 |
| `last_batch` | 动作前图、history 起点、整批动作与预测 |

不再累计命令角度，也不据此推算回位增量。每轮 history 仍须完整匹配上批全部动作，避免重复执行。
模型用 `arm_view=grasp/clearance/other/unclear` 报告当前爪形态；确认低位后，系统只截取这个起点之后
到另一个实图端点的动作。只含同方向肩动作和可选 observe，才可登记为肩的独立经验。
受阻后仍看见低位会重新设置起点，不把此前顶地指令加入下一段。两个方向需分别看图验证且符号相反。

保存就绪图不等于已经学会返回：先从就绪实际降回低位、在下一图确认，才允许进入 pick。
返回时只报告 arm_view=grasp；重新保存 grasp_reference 表示换一套方法，会清空旧就绪图及双向段。
已验证动作只适用于对应起点，从中间位置不能直接复用全程。模型认图仍可能出错，这些校验不是视觉识别器。

执行 elbow 或 arm_pose 后双向动作与 anchor 失效，照片仍保留供恢复；pick 若需要改肘/换预设，须转 explore。
持球投放仍可改肩肘，失败后重新捡球需要重建方法。clearance_reference=null 可主动废弃不可靠的往返关系。

## 投放前的观察边界

投放目的明确为：整颗球高过近侧箱沿，落点在箱口内部并留出球大小的余量。二维重叠不代表前后到位。
第一次看到箱子时保存 bin 目标图，保持闭爪接近或调臂，下一图比较箱沿位置与遮挡变化。
持球松爪需要当轮 `release_check={above_rim:true, inside_opening:true, evidence:...}`；不保存永久放行标记。
校验还要求有接近/调臂之前的 bin 参考图且图片有变化，只有转向/等待不能证明深度关系。

最后一次定位动作与释放不得同批；先定位、取得新图，下一批才决定张爪。张爪后可移开遮挡，下一图确认结果。
仍支持多动作接近以及一次完成降肩、闭爪、抬起；只在必须看结果的地方分批。判断最终仍依赖模型对实图的理解。

当前图、任务、工具和 history 在调用时传入。输入只取 front 图片和工具名/参数；
overhead、仿真 holding、位姿、关节回读、`ok/result` 不进入模型或状态更新。
根据需要发送当前图、上批前图、低位参考、让路参考、持球证据和目标图，按图片内容去重，
最多六张；历史图片明确标注。模型每次重新接收这些内容，不依赖服务端自动记忆。
历史图放在前面，唯一当前图固定放在最后；即使当前图与某张参考像素相同，去重后也保留当前位置和当前 history 边界。
历史 note/learning 中的球位置和“当前”只描述当时。`grasp.region` 约束球心位置，不是球的外接框或目标直径，不能因球轮廓比区域宽就持续后退。

## SQLite 和实验档案

- 临时库：`.cache/langgraph/state.sqlite`，固定 `thread_id="main"`，运行时自动创建。
- SQLite 的 `-wal`、`-shm` 和程序的 `.lock` 都是同一数据库的辅助文件，统一放在缓存目录；`brains/` 只保留代码和设计说明。缓存目录已被 Git 忽略。
- 原采集器每集调用 `reset()`；首轮 `history=[]` 时清理旧 `main` 的 checkpoints
  和图片，再初始化新集。进程重启也按新集处理，不自动重放机器人动作。
- 集内读取最新 checkpoint，保留中间快照及所需图片；JPEG 按内容哈希去重。
  数据库文件锁避免多个实例同时使用 `main`。普通 `openai` Brain 不操作此库。
- 每集另存 `data/langgraph_runs/<时间-后缀>/rounds.jsonl` 和 `images/`，清临时库
  不清档案。构造参数 `db_path/trace_dir` 可以指定独立实验位置。
- 新档案 `format_version=5`：每轮包含 `entry_node`、`action_phase`、独立 `current_scene`、前后状态、请求提示词/图片引用、公开回复、
  token 用量、耗时和 `decisions` 列表。整批判断和预期也写入第一个 Decision 的
  thought，其他动作由原采集器通过 `decision_round` 关联。档案不记录密钥和思考链。

文件分工：`langgraph_brain.py` 负责图、状态更新与批次校验；`langgraph_policy.py` 集中定义
阶段目标、提示词及 `report_plan` 输出契约（语言模型的行为约定，不是 ACT 策略网络）；
`langgraph_memory.py` 负责 SQLite、图片与归档。分开便于调整模型要求时独立审查。
`run_collect.py` 的执行与记录循环保持原样。

自动测试验证批次、状态和输入隔离；它使用模拟模型回复，不能证明视觉探索或抓取成功。
实际能力需查看真实 DeepSeek + MuJoCo 试跑的输入图片、报告和动作轨迹。

## 与 ACT 数据的关系

LangGraph 负责生成演示动作；训练原始数据仍由 `EpisodeRecorder` 存在每个 episode
目录。`decisions.jsonl` 记录高层动作，ACT 需要 `trajectory.jsonl` 和对应车头图片。
收集视觉训练数据时不要加 `--no-images`。

目前没有 ACT 数据转换器或训练入口。转换前需要明确：

1. 观测使用车头图片及部署时真实可用的状态。当前 `arm_qpos + finger + base_pose`
   共 6 维，底盘全局位姿是否可用取决于真机传感器。
2. 动作可以使用当前场景 5 维 `ctrl`（两轮速度、肩/肘目标角、夹爪目标位移），
   按 actuator 名称确认顺序与单位，不能把观测状态直接当作控制命令。
3. `on_tick` 在控制步结束后记录，行 t 的 `ctrl` 是刚执行的命令。若用现有数据
   训练下一步控制，需要将行 t 的观测与行 t+1 的 `ctrl` 对齐并检查采样间隔；
   首个动作缺少动作前观测，末帧缺少下一步标签。
4. 在同集内构造未来动作块，处理尾部 padding/mask，按 episode 划分训练与验证集，
   并筛选演示质量。批量高层决策仍会经过原控制级记录器。

原循环可能在环境判定成功后直接结束，来不及让模型看下一张图；应区分环境成功和
模型视觉确认。未来 ACT 若输出低层动作块，仍需相应执行接口，不能直接当高层工具调用。
