### LangGraph 描述（人类）

我们需要执行以下内容：

（最开始）试出爪子降到最底部时爪子在图像中的位置 $\implies$ 定位出球的“可抓取”范围（球在图像的大概哪个范围内时可以考虑抓取，可以降到最底部时保存图片）和知晓把球丢到盒子里时的“落点”范围（盒子应当大致保住这个范围）。

试出之后需要将爪子抬起来，然后寻找一个看起来没有阻碍的最靠前的球。判断视线里有没有球，如果没有球就**右转**找球（我觉得得限定一个方向，就顺时针吧）。如果有球，选择一个看起来没有障碍的最靠前的球，然后让 deepseek 多模态自己想办法靠近（最靠前是一个有点抽象的说法，但只要确保如果有球在摄像头里那么就会一直在摄像头里就行）。

当看到球到了我们的“可抓取”范围时，我们可以让爪子开始去抓。抓到球之后把爪子抬起来，尽量让爪子和球处于一个：可以在摄像头里看到球和爪子的小部分（出现在摄像头中间顶部），这样我们可以有一个**检验器**判断球是否在爪子上（也即抓到球之后不要把爪子抬的太高，但也一定要抬到上面）。

如果检验器发现球不见了，或者我们抓取失败，我们就要重新回到前面的状态，即找球和捡球。

如果检验器说球还在，我们就开始寻找盒子。如果视线中没有盒子，我们就**右转**。如果找到了盒子，我们就让 deepseek 多模态规划路径然后前进，要求尽可能走不会踩到其他球的路径，但如果实在必须要踩到球，也无所谓因为球会被车推出去，但非必要尽量走空白路径。

当走到盒子里之后，爪子开始往下降，大概降到和盒子差不多的时候就行了。

这是我对 LangGraph 的设想。我们在 langgraph_brain.py 所在的文件夹里建立 langgraph_temporary_file.（文件名后缀是 SQLite 的数据库常用后缀），然后如果 history = None 我们就清空然后启动，thread_id 始终是 "main"，checkpointer 我们应该只会用到最新的。

补充一下，上面是我对流程的设想，状态是希望 AI 能给一个基本补全，然后我会来检验。对于状态，我的一个我认为值得提醒的事情是，你可以把一些关键图片作为状态，例如爪子降到最低点的时候的“可抓取”范围，这个如果我们让 ds 给一个文字 response 然后再把这个 response 放到我们的状态里面，或许，我是说或许，可能直接把这个图片放进来会更直观一些？我的看法，你的状态存储的是重要的最能表达信息的内容。

### LangGraph 描述（AI）

本节与实际提示词 `langgraph_policy.py` 对齐。一个 episode 是一整次捡球投箱任务，当前最多 32 轮看图决策。一轮允许返回一段连续动作；一个阶段可以跨多轮。操作建议写成“一种可行方式”，方向和幅度由当前图片与经验决定。

#### 一、探索：学会一套能重复的抓球动作

探索要回答三个具体问题：爪降到哪里、摆成什么样能夹地上的球；球心来到画面的哪个区域值得抓；怎样抬起看路，再降回去抓。

先认出真正的两根手指及其间的开口，棕色圆关节不是夹爪。如果初始完全看不到手指，目的先是把爪带到可以辨认的位置。（一种可行方式：初始没有待保留的球时张爪、尝试一次前伸姿态，在下一张图辨认手指（仅供参考））

找到低位时可以调整肩和肘：两指大致朝下、指尖贴近地面，两指之间能容纳地上的球。未知方向时，需要比较一次关节变化前后的实际图片：手指离地更近还是更远，朝下还是翻上去。车身不动便于比较；影子辅助判断高度和地面位置。（一种可行方式：保持一个关节不动，另一个先调整约 0.1 弧度，看下一张图；方向清楚后可以连续调整。数值只是例子，正负不是预先标定的升降方向（仅供参考））

当前图已经合适就可以保存，没必要按固定步骤重复调整。保存低位张爪图和可抓球心区域；区域最初是估计，后续抓取会检验并修正它。为了得到低位实图，首次找到低位的动作批需要在那里结束；同批降下又抬回会错过它。

**低位确定后，肘保持不动，只调整肩，把爪抬离地面并让开前方视线。**就绪的意思是：能看清前方的球和路面、爪不拖地。空爪找球时允许爪出画。（一种可行方式：沿已学的有效方向抬肩，下一张图仍被遮挡就继续调整肩，直到视线清楚，再保存就绪图及这段肩的操作（仅供参考））

探索的产物是低位图、就绪图、可抓球心区域和已经看图验证的双向肩动作。保存就绪之后，还需实际降回低位，再由新图确认。指尖已经近地且一次同向调整无明显变化时，应辨认反方向，而不是继续加大顶地动作。约 3-5 轮只是预算提醒。若必须改肘，则在 `explore` 重新建立低位和就绪这对参考，不能沿用旧的只降肩方法却假定它仍可靠。

#### 二、捡球：移动车身对球，再复用降肩动作

找球和接近时保持探索得到的就绪姿态。目标是选中一颗容易接近的绿色球，尽量持续看着它，通过车身转向、前进，让球进入低位参考的可抓区域。（一种可行方式：没看见球时向右找球；看见后选择前方路径较空的一颗，连续转向和接近（仅供参考））

相机固定在车头，因此车身移动会改变球在图中的位置。当前抬高的爪口位置不是地上球应该到达的位置；可抓区域仍来自低位参考图。
该区域约束球心位置，不是球的外接框或理想直径，不能以“球的直径大于区域宽度”为由反复后退。球心已经接近区域时，目的转为看清球与实际两指的关系，或执行已有把握的抓取动作。

距离和对齐已有把握时，一轮可以直接预测到抓后抬起；如果最后一段距离拿不准，就先结束这批，下一轮看清再决定。（一种可行方式：最后一点接近、张爪、按已学肩的操作降回低位、闭爪、抬肩，肘保持低位时的位置（仅供参考））

刚抓完抬肩有两个目的：球离地；下一张图能看见球和部分手指来检查结果。它和空爪找球时完全让开视线的就绪姿态不必相同。（一种可行方式：抬肩至球和少量手指出现在画面上方、前方仍可见；避免直接切换会改变肘的 carry/stow 预设（仅供参考））

下一张图决定分支：

- 看清绿色球被实体手指夹住并离地：转 `place`，可以同轮直接规划找箱。
- 看清两指之间为空：留在 `pick`，目标先是恢复探索得到的就绪姿态再重试。（一种可行方式：张爪、肘不动、按已学肩的操作抬回就绪，再接近；根据抓偏方向修正区域（仅供参考））
- 手指或球被挡住、出画、只见关节或爪背：尚不确定，保留可能的夹持。（一种可行方式：保持闭爪，优先只调肩让球和手指可见（仅供参考））
- 抓球姿态或往返关系不可靠：回 `explore` 恢复或重新建立参考。可能持球时仍保持夹持，不把换阶段当成张爪许可。

#### 三、投放：让球落入箱内，再看结果

运送时需要保持夹持、看清路径和洋红箱。（一种可行方式：保持闭爪，没看见箱时向右搜索，找到后沿较空的路接近（仅供参考））

投放依据是实际绿色球与箱口的位置，目标是球越过箱沿、松开后能落入箱内；此时可以按需要调整肩和肘。球与箱口在画面中重叠不能证明前后位置。（一种可行方式：第一次看见箱子时保存 bin 目标图，保持闭爪，把整颗球抬高到能越过近侧箱沿，再接近箱子；新图对照接近前后的箱沿位置与遮挡关系，确认落点在箱口内部并给球大小留出余量（仅供参考））

最后一次转向、前进或调臂之后，必须先取得新图，再决定释放。模型在当轮 `release_check` 中说明球已高过近沿、落点在箱内的实图依据；代码要求两项确认，并检查存在接近/调臂前的 bin 图，只有转向或等待不够。这是对报告和观察时机的约束，不能代替视觉识别。

释放后的新图确认球在箱内，才有模型完成依据；`done(true)` 单独一批。若看清掉球，则恢复就绪后重捡。投放改过肘时，先恢复原来的抓球关系；没有把握恢复就回探索，不能继续照搬原来的降肩动作。看不清是否持球时保持闭爪改善观察。

#### 四、阶段转移与每轮调用

任务阶段之间的转移由新图决定：

```text
探索 --低位图、就绪图和肩的往返方法可用--> 捡球
捡球 --新图看清球被夹住并离地----------> 投放
投放 --释放后新图看清球在箱内--------> 完成
捡球 --看清抓空----------------------> 恢复就绪后重试（仍在捡球）
投放 --看清掉球且原姿态关系可用------> 恢复就绪后回捡球
捡球/投放 --姿态或往返关系失效-------> 探索
任一阶段 --仍需观察或调整------------> 本阶段继续
```

实际 LangGraph 每轮只运行一个任务节点，通常调用一次模型：

```text
当前车头图 + 已下发指令 + SQLite 中的记忆
                      ↓
START --按 phase 选择 explore / pick / place-- END
        看上批结果、更新经验、预测本批动作
                      ↓
                list[Decision]
                      ↓
       run_collect 顺序执行整批、记录轨迹
                      ↓
                 下一轮新图
```

入口沿用上轮阶段，节点看清当前结果后可在同次报告改 `phase` 并规划下一阶段，无需同图额外调用。动作批中没有新图或条件分支：一批可以连续接近、降肩、闭爪、抬起，但抓空还是抓住由下一轮判断。`observe` 只等待，不在批次中间让模型重新看图。没有独立的试关节、找球、恢复、检查节点。

#### 五、五组跨轮状态：记住能帮助下一步的内容

| 状态 | 保存什么、用来做什么 |
|---|---|
| `phase` | 探索/捡球/投放；决定当前要完成的目的和下一轮入口 |
| `calibration` | `grasp`：低位张爪实图、可抓球心区域；`clearance`：就绪实图；`moves.to_clearance/to_grasp`：两端实图验证过的肩动作及照片边界；`lessons`：最近四条新观察，不能覆盖 moves |
| `arm_anchor` | 最近一次从图中认出的低位/就绪及当时照片；用于截取两个姿态之间的肩动作，不是当前位置、关节角或指令累计量 |
| `visual_memory` | 最近目标图、最近看清持球的图；箱子图用于比较接近或调臂前后的位置，旧图不能证明当前持球 |
| `last_batch` | 动作前图、完整动作列表、history 起点和预期；下一轮核对记录并比较实际结果 |

例如，确认低位后下发肩 -0.3、-0.2，新图确认就绪，系统保存这两个动作；随后下发 +0.2、+0.3，新图确认回低位，才保存返回段。符号只是例子，由实际视觉探索确定。下发过不等于到位，动作只能从对应起点复用；从中间姿态不能照搬完整行程。

每轮 `arm_view` 说明当前爪相对参考的形态：grasp、clearance、other 或 unclear。连续受阻后如果当前仍被认作低位，会重设试验起点，受阻命令不会混入下一次抬肩。系统只保存起止图不同、没有底盘/开合爪/肘/预设混入且同方向的肩动作段；双向段方向必须相反。这里的确认来自模型对实图的判断，不来自仿真真值。

已有 moves 不被每轮文字观察替换。执行 elbow 或 arm_pose 会清空 moves 和 anchor，但保留两端照片供恢复。保存新的 grasp_reference 会清空旧就绪图和 moves；单纯返回原低位只报告 arm_view=grasp。clearance_reference=null 用于废弃不可靠的往返关系。进入 pick 需要双向段，pick 中需要改肘或预设时须改回 explore。

参考只能保存当前收到的实图。已执行张爪且没有可能持球记录时，可保存能辨认的张爪几何参考，即使 `holding=unclear`；只有关节或影子不够。就绪参考使用 `clearance_reference={save_current:true,note:...}`，省略表示未更新，null 表示废弃。

Brain 只使用车头图、工具定义、模型的视觉报告和指令名/参数；仿真位姿、持球真值、其他相机及 `ok/result` 不进入推理和记忆更新。当前图、上批前图、低位、就绪、目标和持球图按内容去重后发给模型，最多六张。
历史图在前、唯一当前图在最后；即使像素与旧参考相同，也保留当前图的标签和动作边界。历史文字中的球坐标、大小和“当前”不能覆盖最后一图中的实际场景。

#### 六、实现与检查

`langgraph_policy.py` 集中写上面的目的、建议和输出字段，`langgraph_brain.py` 负责三个节点与校验，`langgraph_memory.py` 负责 SQLite 和图片档案。终端显示入口阶段与本批动作阶段，阶段变化可直接看到。

为保持代码目录整洁，临时库现改为项目根目录下的 `.cache/langgraph/state.sqlite`，不再使用上方原始设想中的代码目录位置；`thread_id="main"`。原采集器每集 reset，首轮 history 为 []，清理上一集临时状态；历史实验档案独立保留。普通 openai brain 不操作此库。

`run_collect.py` 的执行和记录接口不变。自动测试检查批次、记忆与输入隔离；实际模型能否认对爪、抓住球，要通过真实图片试跑验证。ACT 转换和训练尚未实现，现有控制级轨迹仍由原记录器采集。
