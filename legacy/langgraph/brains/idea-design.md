# LangGraph 架构草案：简单判断、固定动作、按需经验

本文是下一版设计，不代表当前代码已经实现。

目标：把“找球、抓球、放进箱子”拆成可单独检验的小任务。模型负责看图和局部判断；程序负责阶段、记忆检索和执行。需要某种经验时才读取，没有时才建立，不再每集从头探索肩肘。

## 1. 先确定机械臂能做什么

第一版以提前调好的 `stow / carry / reach / drop` 为基础，暂不让任务模型自由使用 `shoulder / elbow`。预设本身可以同时改变肩肘，不要求整个任务固定肘。

先验证一个统一的起止臂姿态 `home`，优先尝试 `carry`：既能行驶看路，又能在持球时看见必要的球和夹指。若现有预设做不到，先调整预设配置，不让每集任务反复试关节。

程序将基础工具组织成两个组合动作；它们是内部子流程，不是新增硬件能力：

| 组合动作 | 固定流程 | 需要新图的地方 |
| --- | --- | --- |
| 抓取 | `home → 张爪 → reach → 闭爪 → home` | 到 `reach` 后检查球与实体夹指；回 `home` 后检查是否持球 |
| 投放 | `home（保持闭爪）→ drop → 张爪 → home` | 到 `drop` 后检查能否释放；释放后检查球去了哪里，必要时移开臂再看 |

检查不通过就暂停组合动作，不继续闭爪、松爪。组合动作期间底盘保持停止；需要开车重新对位时，先恢复已验证可行驶的 `home`，再移动。

“起止姿势一致”指机械臂回到同一个绝对目标姿态；夹爪开合与是否持球当然会改变。返回使用预设目标，不靠累计肩肘增量推算。

抓取位置参考分为“候选”和“实际抓成功后验证”：空爪图可以给出候选，不能提前证明成功。若组合动作中途移动了车、更换了目标或偏离了预定臂姿态，原来的对位判定需要重做。

## 2. 视觉提取：原图转成小而明确的 JSON

每次只提取当前图中的可见对象及关系，不决定阶段、不安排动作。保留原图，JSON 无法表达或看不清的地方允许 `unknown`。

对象包括：球、实体夹指、指间开口、掌和遮挡视线的臂段、箱体、箱口、近侧箱沿、外壁、地面、障碍物，以及可供前后比较的静止参照物。影子与实体分开记录。按当前图实际可见内容输出，不强行补全。

结构示例（仅说明格式）：

```json
{
  "frame_id": "f12",
  "objects": [
    {"id": "b1", "kind": "ball", "box": [0.42, 0.61, 0.50, 0.69], "visibility": "clear"}
  ],
  "relations": [],
  "unknown": ["夹爪是否持球"]
}
```

- 坐标统一为左上原点、范围 0～1；箱口等非矩形区域可增加轮廓点。
- `relations` 记录对象之间可见的遮挡、包含等关系；二维重叠不直接变成“三维接触”。
- 对象编号先只在当前帧有效。跨帧是不是同一颗球，由单独的比较任务确认；无法确认就不强行关联。
- JSON 便于程序筛选与定位；抓住、可释放等关键判断仍可读取原图及必要的前后图。

## 3. 阶段：程序维护进度，每个阶段只解决一个问题

共同执行循环：

```text
取得新图 → 视觉提取 → 保存上次动作的前后经验 → 程序路由当前阶段
    → 按需检索经验 / 做一个局部判断 → 下发动作或切换阶段
    → 有动作时结束本轮，执行后再取新图
```

图中走过一个节点不等于机器人动过，也不等于拿到了新图。程序按动作编号提交执行记录，恢复运行时不重复执行已完成的动作。

| 阶段 | 唯一要解决的问题 | 结果与去向 |
| --- | --- | --- |
| 适应 1：准备组合动作 | 当前配置是否已有可用预设、组合动作和参考图？ | 有则跳过；没有则验证并保存候选参考，不在这里反复空爪探索；真实抓取再检验候选 |
| 定向 1：找球 | 当前图能否选定一颗可接近的球？ | 没有则分段右转；有则锁定目标，进入适应 2 / 判定 1 |
| 适应 2：补运动经验 | 下一次移动有没有可用的相似经验？ | 有则跳过；没有则做一次有参照物的试探，保存前后图后回调用它的阶段 |
| 判定 1：对准抓取位置 | 目标是否满足组合动作的起始条件？ | 是则进入抓取；否则输出左偏、右偏、偏远、偏近或未知，交给移动模块修正 |
| 抓取 | 完成固定抓取组合动作 | `reach` 后局部检查通过才闭爪；回 `home` 后进入抓取确认 |
| 抓取确认 | 新图是否支持已经持球？ | 是则定向 2；明确空爪则重新对位；未知则保持夹爪命令并改善观察 |
| 定向 2：找箱 | 持球时能否看到目标箱？ | 没有则分段右转；有则锁定箱子，进入判定 2 |
| 判定 2：对准投放位置 | 当前是否适合把臂送到投放姿态？ | 否则移动或观察；是则保持闭爪切到 `drop`，取得新图再做释放检查 |
| 放下 | 当前球向下落能否进入箱口、不撞沿？ | 是才张爪并恢复；否则保持闭爪，返回对位或改善观察 |
| 投放确认 | 新图是否支持球已落进箱内？ | 是则完成；落在地上则重捡；未知则继续观察，不凭张爪指令宣布成功 |

补充几个边界：

- “最近”只在当前可见、可接近的球中选择，不要求先扫描全场或知道真实距离；无法区分远近时选路径较空的一颗。短暂遮挡不自动换目标。
- 判定 1 的参考要绑定 `home`、相机和组合动作版本。初期模型比较当前图与参考；积累成功样本后，程序可以先做区域筛选，但入框不替代 `reach` 后的夹指对位检查。
- 判定 2 的“手够得到”只是准备条件。松爪依据是球与箱口、近沿的实际关系，必要时比较接近前后图。
- 持球状态只设 `empty / held / unknown`。未知不等于空爪；明确掉球时返回找球，姿态配置失效时返回适应 1。
- 适应 2 是共享子流程，找球、对球、找箱、对箱都能按需调用；不是只在定向 1 后执行一次。

## 4. 移动经验：缺哪一种，再学哪一种

“速度概念”先理解为：在类似画面下，某个动作持续一段时间，会造成怎样的可见变化。没有距离标定时，不要求模型算出米每秒，也不把像素变化当成恒定速度。

前进、后退、左转、右转分别积累经验。一次试探只建立初步参照，不代表速度已被精确标定；一次前进样本也不证明已经了解其他三种动作。找球时的右转本身可以成为右转经验。

一次经验的最小记录：

```text
配置版本 + 动作前图片/JSON + 实际执行的工具与参数
         + 动作后图片/JSON + 同一参照物的匹配 + 可见变化/未知
```

使用过程：

1. 当前阶段提出目的，例如“让这个球更接近抓取位置”。
2. 程序检索同一动作、相似目标远近与视角下的 1～2 个样本，提供原始前后图和实际动作。
3. 有适用样本：模型只选下一小段动作与时长；程序检查参数范围后执行。
4. 没有适用样本：进入试探。定向 1 后，目标较远且前方有足够可见空间时，可以先前进一个配置好的中等时长；已经很近或路径不明时，改用更短动作或先观察。
5. 取得新图后记录实际变化。若目标丢失、被碰动、参照物匹配不清，标记为不可用于该目标的运动估计，不编造位移。

试探时保持臂姿态不变，一次只做一种底盘动作。参照物选静止的箱沿、地砖等；球可用于观察接近效果，但被推动后不能当静止参照物。与相机同车运动的夹爪不用于估计底盘移动效果。

每次移动后重新判断。距离变化、转弯、遮挡、负载或地面条件变化后，旧经验可能不再适用；保存失败和“几乎没变化”的样本，避免反复照搬无效动作。

## 5. 数据库与 LangGraph 各管什么

SQLite 足够起步，不先引入向量数据库。图片保存为文件，库中保存引用和可筛选字段。

| 内容 | 保存什么 | 生命周期 |
| --- | --- | --- |
| 当前任务状态 | 阶段、目标、持球判断、组合动作进度、待执行/已执行动作编号、当前帧和待比较前帧 | 每个 episode 重置，由 checkpointer 管理 |
| 组合动作库 | 起止姿态、动作序列、观察检查点、参考图、适用配置、候选/已验证状态 | 跨 episode 保留 |
| 运动经验库 | 前图、实际动作、后图、参照物、变化、适用条件和失败记录 | 跨 episode 保留，按需检索 |

机械臂、相机安装、预设角度或驱动参数改变时，相关经验需要重新验证，不能无条件沿用。重置任务不清空经验库；检索不到适用经验就建立新样本。

LangGraph 的作用是记录“当前缺什么”，路由到读取经验、补经验、执行或验证。它不需要让一个模型每轮重新解释全部任务历史。图片和结果按实际执行关联，计划和预测不冒充经验。

## 6. 模型只承担五种小任务

节点可以复用同一个模型，但输入和输出各自独立；程序路由、数据库读写、参数校验和固定动作执行都不需要 prompt。
阶段数不等于模型调用次数：每张新图提取一次，只调用当前需要的小任务，不把下表全部跑一遍。

| 小任务 | 给模型什么 | 只要求输出什么 |
| --- | --- | --- |
| 提取 | 当前原图 | 对象与可见关系 JSON |
| 选择目标 | 当前图与候选对象 | 一个对象编号，或“没有/未知” |
| 比较 | 两张图和待匹配对象 | 是否同一对象、可见变化，或“未知” |
| 局部检查 | 当前图、必要参考、一个问题 | 一个枚举结果和一句依据，如 `yes / no / unknown`，或对位偏差方向 |
| 选择移动 | 一个对位目的、当前图、至多两条经验 | 一条底盘动作及时长，或 `need_sample(tool)` / “需要观察” |

局部检查每次只问一件事，例如“球在两夹指之间吗”“已经持球吗”“现在可以释放吗”。不同时要求它规划接近、预测抓取、判断持球和安排投放。
`need_sample(tool)` 表示缺少指定动作的经验，程序据此检索或进入适应 2；取得新样本后，再回原阶段重新判断。

提示词保持一句任务说明加固定输出协议。长期经验存库，临时案例通过检索提供，不把每次失败都追加成新的长提示词。模型声称“七成把握”不直接控制阶段；关键关系未知时补相关证据或取得新图。连续没有新证据或进展时停止重复尝试，记录未完成原因。

## 7. 对三个疑问的决定

**肩肘是否也要建立概念？** 第一版不必建立通用的角度到图像变化模型；使用已调好的预设，只验证组合动作和适用位置。以后开放微调时，再按“前图＋单关节动作＋后图”积累局部经验，且要记录起始姿态；相同增量在不同姿态下不能视为相同效果。

**肘是不是基本不动，开始先配成九十度？** 不规定九十度。抓取、携带和投放各自的肘角由预设配置决定。任务模型不随意改肘，但切换预设可以改变肘。原设想的“外翻肘、降肩、放球、恢复”优先交给已验证的投放子流程，不让模型每次重新组合。

**是否先转九十度建立空间直觉？** 第一版不要求完整空间地图。用分段右转寻找目标，用有共同参照物的前后图学习局部转向效果。大转角容易让目标出画；当前工具参数是秒，未确认实际转角时，也不能把一次右转记成九十度。非 reasoning 模型只做当前图中的识别、比较和下一步选择，是否足够由测试判断。

## 8. 最小验证顺序

1. 验证预设与抓取、投放子流程，确定统一 `home` 和关键参考图。
2. 用固定图片分别检验提取、目标选择、局部判断；标签由人工核对或仅用于评估的仿真真值提供，不把 reasoning 输出直接当答案。
3. 跑通找球、补运动经验、对位、抓取确认，再接找箱、投放确认。移动、抓取、释放之间保留明确的新图边界。
4. 固定按场景/episode 分开的测试集，每次只替换一个节点的模型或 prompt；比较关键误判、成功率、调用次数和耗时，再做完整闭环验证。

真机输入保持为相机图像、已执行命令和可迁移经验；底层驱动可用编码器完成运动，不向任务模型提供仿真物体坐标或吸附结果。仿真中的抓取成功还需经过真机实际夹持验证。
